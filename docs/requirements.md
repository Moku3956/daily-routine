
# 習慣クエスト
## 機能要件
### コンディション管理機能
#### コンディション入力機能
- 入力項目：体力、やる気
- 処理内容：
  - 一日のはじめに入力をもとめる通知
  - 入力項目それぞれ5段階表示
  - 入力結果を出力
　- 入力に応じたランク：
  　- 合計値が、8以上の場合、"好調"
  　- 合計値が、5以上7以下の場合、"普通"
  　- 合計値が、4以下の場合、"不調"
- 例外処理：
  - 入力する前にブラウザバックした場合の再表示
  - 入力をしない場合の"入力が完了していません"みたいな警告を出し、
  　入力させるまで画面を変えない。

### 習慣管理
#### 習慣追加機能
- 入力項目：習慣、カテゴリ、コスト、マスト性
- 処理内容：
  - 習慣、カテゴリ、コスト、マスト性を追加
- 各項目の詳細：
  - 習慣：処理したいタスク
  - カテゴリ：その習慣の種類
  - 目標値(回数、時間): 単位を回数か時間か選択し、数字を入力
  - コスト：肉体的なコスト(1-10)、精神的なコスト(1-10)の2つ
  - マスト性：必ず行う、またはできれば行うの2つ
- 例外処理
  - 項目をすべて埋めなかった場合追加しない

#### 習慣調整機能
- 出力項目：コンディションに応じた、習慣の順番リスト
- 処理内容：
- 順番決定処理
  - マスト性が高いものはリストの上位に配置
  - "好調"または"普通"の場合、コストを降順
  - "不調"の場合、コストを昇順
  - 例外処理（コストが同じだった場合）
  - 体力とやる気が同じ場合
    - ランダムに順序を決める
  - 体力のほうが大きい場合
    - 肉体的コストが大きいほうが上位
  - やる気のほうが大きい場合
    - 精神的コストが大きいほうが上位
  - "不調"の場合は、逆の処理を行う

- 分量調整
  - "好調"の場合、"必ず行う"の目標値を120％に設定(例：60分->72分)
  - "好調"の場合、"できれば行う"習慣を目標値通りに設定
  - "普通"の場合、すべての習慣を目標値通りに設定
  - "不調"の場合、習慣を"必ず行う"のみにして、目標値の50％に設定

- 例外処理：
  - 端数は四捨五入

### 統計機能
#### 連続習慣記録機能
- 出力項目
  - 習慣を達成できた連続日数
- 処理内容：
　- その日に提示された習慣が行われたかチェック
　- すべて行われた場合、カウントを１追加
　- 振り返り時に未達成の場合、０に更新
- 例外処理
  - コンディションを入力していなければ、０に戻す
  - 未達成かつ振り返りを行わなかった場合、次回ログイン時に０に更新

### 振り返り機能
#### 習慣完了チェック
- 入力項目：習慣のチェック（タスクバー形式）
- 処理内容：
  - 前日の習慣がチェックされていなければ、コンディションを入力する前に確認
- 例外処理
  - 一度も習慣を追加していない場合（初日）、完了扱い

### ユーザー認証機能
#### ユーザー登録機能
- 入力項目: ユーザー名、パスワード、パスワード（確認用）

- 処理内容:
  - ユーザー名をユニーク（重複不可）として登録。
  - パスワードはハッシュ化してデータベースに保存。
- 例外処理:
  - すでに存在するユーザー名が入力された場合、エラーを表示する。
  - 確認用パスワードが一致しない場合、再入力を求める。

#### ログイン機能
- 入力項目: ユーザー名、パスワード
- 処理内容:
  - データベースからユーザー名を照合し、パスワードと一致するか検証。
  - 認証成功時、セッションを発行し、ログイン状態を維持。

- 例外処理:
  - ユーザー名またはパスワードが間違っている場合、「ログインに失敗しました」と表示。

#### ログアウト機能
- 処理内容:
  - 現在のセッションを破棄し、ログイン前の状態へ戻す。


## 非機能要件
- バックエンドはGoを採用し、Hexagonal Architectureで設計する。
- ドメイン層は `internal/domain` を中心に配置し、アダプター層との疎結合を維持する。
- Web APIはGin、DBアクセスはGORM、データベースはPostgreSQLを採用する。
- 依存注入は `main.go` で手動DIを行う。
- フロントエンドはNext.js（App Router）+ TypeScriptを採用する。
- スタイリングはTailwind CSS、UI部品はshadcn/uiを採用する。
- 状態/通信管理はTanStack Queryを採用する。
- PWA（next-pwa）に対応し、ブラウザからインストール可能にする。

### 技術スタック一覧

#### バックエンド
| 役割 | 技術 | 備考 |
| --- | --- | --- |
| 言語 | Go | シンプルで高速。並行処理が得意。 |
| 設計手法 | Hexagonal Architecture | `internal/domain` を中心とした疎結合な設計。 |
| Webフレームワーク | Gin | 左側アダプター。高速なHTTPルーティング。 |
| ORM | GORM | 右側アダプター。DB操作をGoの構造体で完結。 |
| データベース | PostgreSQL | 構造化データの保存。拡張性が高い。 |
| DI（依存注入） | 手動DI | `main.go` で各パーツを接続する。 |

#### フロントエンド
| 役割 | 技術 | 備考 |
| --- | --- | --- |
| フレームワーク | Next.js (App Router) | Reactベース。最新のレンダリング手法。 |
| 言語 | TypeScript | 型安全により、API通信のバグを減らせる。 |
| デザイン/CSS | Tailwind CSS | ユーティリティファーストで高速スタイリング。 |
| UI部品庫 | shadcn/ui | モダンなコンポーネントを即座に導入。 |
| 状態/通信管理 | TanStack Query | APIからのデータ取得・キャッシュ・同期を管理。 |
| アプリ化 | PWA (next-pwa) | ブラウザから「アプリとしてインストール」可能に。 |
